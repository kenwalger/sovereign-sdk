## Code Style Rules

### Python

**Type Annotations & Modern Generics**
All functions, methods, class attributes, and module-level variables require strict PEP 484 type annotations. You must use modern, native collection generics (`list[str]`, `dict[str, Any]`, `tuple[int, ...]`) to support Python 3.12+. Importing obsolete collection typing wrappers (`typing.List`, `typing.Tuple`, `typing.Dict`) is explicitly prohibited. `Any` is banned unless an engineering reason is explicitly documented inline with a `:type:` qualifier.

**Docstrings**
All public functions, models, methods, and classes require Sphinx-style docstrings. Every parameter, its type, the return value, and the return type must be explicitly declared according to the repository's precise technical register.

```python
def verify_receipt(receipt: ForensicReceipt, context: dict[str, Any], expected_public_key: str) -> bool:
    """
    Cryptographically validate an active ForensicReceipt using an external anchor.

    :param receipt: The self-contained tamper-evident forensic transaction ledger.
    :type receipt: ForensicReceipt
    :param context: The verification payload dictionary containing the sieved string content.
    :type context: dict[str, Any]
    :param expected_public_key: The trusted, out-of-band base64 Ed25519 public key.
    :type expected_public_key: str
    :return: True if the signature matches the manifest hash and matches the trusted anchor.
    :rtype: bool
    :raises CryptographicError: If signature validation fails due to key mismatch.
```

## Additional Architectural Constraints

- Zero Raw Exceptions: No bare `except:` clauses. Always catch explicit exception classes. Ensure cleanup paths (`finally` blocks) defensively catch ambient file-system errors so they never suppress or mask primary `SovereignStorageError` exceptions.
- Transactional File & Data Operations: All disk mutations (key writes, configuration saves, block appends) must utilize a transactional staging pattern (`tempfile` + atomic `os.replace`). Dual-file writes must feature explicit, multi-layered rollback logic to prevent split-state corruption.
- Database Mutability Triggers: When interacting with embedded storage layers (`sqlite3`), you must natively configure optimization pragmas (`WAL` mode, `FOREIGN_KEYS = ON`, `SYNCHRONOUS = NORMAL`). You must strictly enforce write-side custody invariants using database-level `BEFORE UPDATE` and `BEFORE DELETE` triggers to completely exterminate mutation capabilities.
- Dependency Minimalism: Core packages must run completely offline on local silicon with zero network dependencies or high-compute model runtimes (PyTorch, transformers, etc.).

## Autonomy & Non-Attribution Constraints
These are hard behavioral constraints governing all agent activity in this repository.

1. No self-attribution in any file. Do not insert comments or annotations such as # Generated by AI, // Assisted by Claude, or any semantically equivalent phrase.
2. No signature blocks in documentation. Do not append AI model identifiers, generation timestamps, or automated provenance markers to markdown files or headers.
3. No machine provenance in commit messages. Do not append Co-authored-by: lines referencing AI systems or automated pipelines.
4. Maintain professional code register. Avoid explanatory comments on self-evident code operations. All commentary must be precise, economical, and authoritative—avoiding hedging, casual language, or meta-commentary.
